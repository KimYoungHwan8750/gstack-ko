# gstack-ko

[garrytan/gstack](https://github.com/garrytan/gstack)의 한국어 fork.

gstack은 Claude Code를 가상 엔지니어링 팀으로 만들어주는 스킬 모음입니다. CEO가 제품을 재정의하고, 엔지니어링 매니저가 아키텍처를 확정하고, 디자이너가 AI slop을 잡아내고, 리뷰어가 프로덕션 버그를 찾고, QA가 실제 브라우저를 열고, 보안 책임자가 OWASP + STRIDE 감사를 돌리고, 릴리스 엔지니어가 PR을 배포합니다. 전부 슬래시 커맨드, 전부 Markdown, 전부 무료, MIT 라이선스.

## 원본과 다른 점

| 항목 | 내용 |
|------|------|
| **한글화** | 28개 스킬 전체 + 지원 파일 6개 한글 번역. 고유명사/개발용어/코드블록은 원문 유지. |
| **yhlib 통합** | yhlib 모노레포 자동 감지 시 프레임워크 선택 건너뛰기, 확정 스택 참조, `apps/` 앱 선택 안내. 미감지 시 기존 동작 유지. |
| **한국 규제/문화** | CSO에 개인정보 보호법/정보통신망법 점검, benchmark에 한국 기업 성능 기준, office-hours/plan-ceo-review에 한국 스타트업 생태계 컨텍스트 추가. |
| **업그레이드** | `git reset --hard` 대신 three-way merge로 한글화 보존하며 upstream 병합. |

## 빠른 시작

```bash
# clone
git clone -b ko https://github.com/KimYoungHwan8750/gstack-ko.git ~/.claude/skills/gstack

# upstream 등록 (업그레이드용)
cd ~/.claude/skills/gstack
git remote add upstream https://github.com/garrytan/gstack.git
```

Claude Code 재시작하면 스킬이 활성화됩니다. 상세 설치 가이드는 [SETUP.md](SETUP.md)를 참조하세요.

### browse 스킬 활성화 (선택)

`/browse`, `/qa`, `/design-review` 등 브라우저 기반 스킬을 쓰려면:

```bash
cd ~/.claude/skills/gstack
bun install && bun run build && ./setup
```

## 스킬 목록

### 스프린트 워크플로우

**생각 → 계획 → 구현 → 리뷰 → 테스트 → 배포 → 회고**

각 스킬은 스프린트 순서대로 나열되어 있으며, 이전 스킬의 산출물을 다음 스킬이 자동으로 참조합니다.

---

#### `/office-hours` — YC 오피스 아워

**역할:** 아이디어 브레인스토밍 + 디자인 문서 작성

코드를 쓰기 전에 **무엇을 만들 것인지** 확정하는 스킬. 스타트업 모드(6가지 강제 질문으로 수요/경쟁/쐐기 검증)와 빌더 모드(사이드 프로젝트/해커톤용 자유 브레인스토밍) 두 갈래로 나뉩니다. 전제 도전, 대안 생성, 디자인 문서 작성까지 한 세션에 끝냅니다.

**언제 호출:** "아이디어가 있는데", "이거 만들 가치가 있을까", 새 프로젝트 시작 전. 코드 전에 반드시 먼저.

---

#### `/plan-ceo-review` — CEO / 창업자 리뷰

**역할:** 문제 재정의, 10-star 제품 찾기, 범위 결정

플랜 파일을 읽고 **더 크게 생각할 여지**가 있는지 도전합니다. 네 가지 모드: 범위 확장(SCOPE EXPANSION), 선택적 확장(SELECTIVE EXPANSION), 범위 유지(HOLD SCOPE), 범위 축소(SCOPE REDUCTION). Bezos/Munger/Jobs 등의 인지 패턴을 적용하여 전략적 블라인드스팟을 찾습니다.

**언제 호출:** `/office-hours` 후 플랜이 나왔을 때, "이게 충분히 야심적인가?", 범위를 넓히거나 좁혀야 할 때.

---

#### `/plan-eng-review` — 엔지니어링 매니저 리뷰

**역할:** 아키텍처 확정, 실행 계획 검증

플랜의 **기술적 실행 가능성**을 검증합니다. ASCII 다이어그램으로 데이터 흐름/상태 머신을 그리고, 엣지 케이스/실패 모드/테스트 매트릭스를 도출합니다. "Choose Boring Technology" 원칙 기반으로 과잉 엔지니어링도 잡습니다.

**언제 호출:** 플랜 승인 후 코딩 시작 전, "아키텍처 괜찮은지 봐줘", 구현에 불확실성이 있을 때.

---

#### `/plan-design-review` — 시니어 디자이너 리뷰

**역할:** UI/UX 관점 플랜 평가

디자인 차원별 0-10 점수를 매기고, 10점이 되려면 무엇이 필요한지 구체적으로 제안합니다. AI Slop(AI가 만든 저품질 디자인 패턴) 감지. 플랜 모드에서 동작하며 코드를 수정하지 않습니다.

**언제 호출:** UI/UX 컴포넌트가 포함된 플랜이 있을 때, 구현 전 디자인 크리틱이 필요할 때.

---

#### `/design-consultation` — 디자인 파트너

**역할:** 디자인 시스템 구축 + DESIGN.md 생성

제품을 이해하고 시장을 조사한 뒤, 타이포그래피/색상/레이아웃/간격/모션을 포함한 **완전한 디자인 시스템**을 제안합니다. 폰트+색상 미리보기 페이지도 생성. DESIGN.md를 프로젝트의 디자인 진실의 원천으로 남깁니다.

**언제 호출:** 새 프로젝트에서 디자인 시스템이 없을 때, "브랜드 가이드라인 만들어줘", DESIGN.md가 필요할 때.

---

#### `/review` — 스태프 엔지니어 (PR 리뷰)

**역할:** 사전 착륙(pre-landing) 코드 리뷰

base 브랜치 대비 diff를 분석하여 **CI가 못 잡는 버그**를 찾습니다. SQL 안전성(인젝션, N+1), LLM 신뢰 경계 위반, 경쟁 조건, 조건부 부작용, scope drift(범위 이탈) 검출. 명백한 이슈는 자동 수정, 판단이 필요한 건 AskUserQuestion.

**언제 호출:** PR 생성 전, "코드 리뷰 해줘", merge 전 최종 점검.

---

#### `/investigate` — 디버거

**역할:** 근본 원인 조사를 통한 체계적 디버깅

**철칙: 근본 원인 없이 수정하지 않는다.** 4단계(조사→분석→가설→구현)로 진행하며, 3번 실패하면 에스컬레이션합니다. 경쟁 조건, nil 전파, 상태 오염 등의 패턴을 분석합니다.

**언제 호출:** "왜 이게 안 돼?", 에러 트레이스백을 보고 있을 때, 원인 불명의 버그.

---

#### `/design-review` — 코딩하는 디자이너 (시각 QA)

**역할:** 라이브 사이트 시각 QA + 소스 코드 직접 수정

헤드리스 브라우저로 실제 페이지를 열어 간격/정렬/색상/타이포 문제를 찾고, **소스 코드에서 직접 CSS/JSX를 수정**합니다. 각 수정을 원자적으로 커밋하고 전후 스크린샷으로 재검증.

**언제 호출:** "디자인 좀 다듬어줘", 시각적 불일치 발견 시, 배포 전 외관 점검. 브라우저 빌드 필요.

---

#### `/qa` — QA 리드

**역할:** 실제 브라우저로 테스트 → 버그 찾기 → 수정 → 재검증

헤드리스 Chromium으로 사용자 흐름을 실제로 클릭하며 테스트합니다. 발견된 버그를 소스에서 수정하고, 원자적 커밋 후 재검증. 3단계 등급: Quick(심각/높음만), Standard(+보통), Exhaustive(+외관). 전후 건강 점수 제공.

**언제 호출:** "이거 작동해?", 기능 완성 후 테스트, staging URL 점검. 브라우저 빌드 필요.

---

#### `/qa-only` — QA 리포터

**역할:** 테스트만 하고 수정하지 않는 버그 리포트

`/qa`와 동일한 방법론이지만 **코드를 건드리지 않습니다**. 건강 점수, 스크린샷, 재현 단계가 포함된 구조화된 리포트만 생성.

**언제 호출:** 다른 사람이 수정할 버그 리포트가 필요할 때, 코드 변경 없이 현황 파악.

---

#### `/cso` — 보안 책임자 (Chief Security Officer)

**역할:** 인프라 우선 보안 감사

14단계 감사: 아키텍처 멘탈 모델 → 시크릿 고고학 → 의존성 공급망 → CI/CD → OWASP Top 10 → STRIDE 위협 모델링 → 데이터 분류 → 한국 개인정보 보호법(PIPA)/정보통신망법 점검. 두 모드: 일일(8/10 신뢰도, 제로 노이즈)과 종합(2/10, 월간 정밀 스캔).

**언제 호출:** 배포 전 보안 점검, "보안 감사 돌려줘", 개인정보 처리 기능 추가 후.

---

#### `/ship` — 릴리스 엔지니어

**역할:** 테스트 → diff 리뷰 → VERSION 범프 → CHANGELOG → push → PR 생성

코드가 준비되면 **한 명령으로 PR까지** 만듭니다. 테스트 프레임워크가 없으면 부트스트랩하고, 커버리지 감사, 범위 이탈 검출, 이등분 가능한(bisectable) 커밋 분리까지 수행.

**언제 호출:** "ship 해줘", "PR 만들어줘", 코드가 준비됐을 때.

---

#### `/land-and-deploy` — 릴리스 엔지니어 (배포)

**역할:** PR merge → CI 대기 → 프로덕션 헬스 체크

`/ship`이 만든 PR을 **merge하고 프로덕션까지 검증**합니다. CI 완료 대기, 배포 상태 확인, 카나리 체크로 프로덕션 건강 확인.

**언제 호출:** PR이 승인된 후, "merge하고 배포해줘", `/ship` 다음 단계.

---

#### `/canary` — SRE (배포 후 모니터링)

**역할:** 배포 후 라이브 앱 감시

browse 데몬으로 주기적으로 스크린샷을 촬영하고, 배포 전 베이스라인과 비교합니다. 콘솔 에러, 성능 회귀, 페이지 장애를 감지하면 알림.

**언제 호출:** 배포 직후, "프로덕션 모니터링 해줘". 브라우저 빌드 필요.

---

#### `/benchmark` — 성능 엔지니어

**역할:** Core Web Vitals 기준선 수립 + PR별 전후 비교

TTFB, FCP, LCP, 번들 크기, HTTP 요청 수를 측정하고 회귀를 감지합니다. 한국 기업(Toss, Coupang, Kakao, Naver) 성능 기준도 참고. `--trend` 모드로 시간 경과 추세 추적.

**언제 호출:** 성능 최적화 작업, "페이지 속도 측정해줘", PR의 성능 영향 확인. 브라우저 빌드 필요.

---

#### `/document-release` — 테크니컬 라이터

**역할:** 배포 후 문서 자동 업데이트

diff와 교차 참조하여 README, ARCHITECTURE, CONTRIBUTING, CLAUDE.md, CHANGELOG를 **실제 배포 내용에 맞게** 업데이트합니다. 오래된 문서를 자동 감지.

**언제 호출:** PR merge 후, "문서 업데이트해줘", `/ship` 이후 자동 제안됨.

---

#### `/retro` — 엔지니어링 매니저 (주간 회고)

**역할:** 커밋 히스토리 분석 + 코드 품질 추세 + 개인별 기여도

지난 주 커밋을 분석하여 배포 속도, 테스트 건강도, 코드 복잡도 추세를 보여줍니다. 팀 모드에서는 개인별 기여도를 칭찬/성장 영역과 함께 분석. `retro global`로 모든 프로젝트 통합 회고 가능.

**언제 호출:** 주말/스프린트 종료 시, "이번 주 뭐 했지?", 팀 회고.

---

#### `/browse` — QA 엔지니어 (헤드리스 브라우저)

**역할:** 영구 헤드리스 Chromium — 명령당 ~100ms

다른 스킬(`/qa`, `/design-review`, `/benchmark`, `/canary`)의 **엔진**. 직접 호출하면 URL 탐색, 요소 클릭, 폼 작성, 스크린샷, 반응형 테스트, 쿠키 관리 등을 수행합니다.

**언제 호출:** "이 사이트 열어봐", "스크린샷 찍어줘", 특정 URL의 상태 확인. 브라우저 빌드 필요.

---

#### `/autoplan` — 리뷰 파이프라인

**역할:** CEO → 디자인 → 엔지니어링 리뷰를 한 번에 자동 실행

15~30개의 중간 질문에 일일이 답하지 않고, 6가지 의사결정 원칙으로 **자동 판단하며 순차 리뷰**합니다. 취향 결정(근접한 접근법, 경계선 범위)만 최종 승인 게이트에서 물어봅니다.

**언제 호출:** 플랜이 있고 전체 리뷰를 빠르게 돌리고 싶을 때, "알아서 리뷰해줘".

---

### 유틸리티

#### `/codex` — Codex 세컨드 오피니언

OpenAI Codex CLI 래퍼. 세 가지 모드: **리뷰**(pass/fail 게이트), **챌린지**(코드를 깨뜨리려는 적대적 모드), **상담**(자유 질문). `/review`와 함께 쓰면 크로스 모델 분석 제공.

**언제 호출:** "다른 AI 의견도 듣고 싶어", 중요한 아키텍처 결정 전 세컨드 오피니언.

---

#### `/careful` — 안전 가드레일

`rm -rf`, `DROP TABLE`, `git push --force`, `git reset --hard` 등 파괴적 명령어 실행 전 경고. 각 경고를 개별 재정의 가능.

**언제 호출:** 프로덕션 DB 작업, 라이브 시스템 디버깅, "조심 모드 켜줘".

---

#### `/freeze` — 편집 범위 잠금

세션 동안 파일 편집을 **지정한 디렉토리로 제한**. 디버깅 중 관련 없는 코드를 실수로 수정하는 것을 방지.

**언제 호출:** "이 폴더만 수정해", 특정 모듈에 집중하고 싶을 때.

---

#### `/guard` — 전체 안전 모드

`/careful` + `/freeze` 결합. 파괴적 명령어 경고 + 편집 범위 제한을 동시에 적용.

**언제 호출:** 프로덕션 환경 작업, "최대 안전 모드로".

---

#### `/unfreeze` — freeze 해제

`/freeze`로 설정된 편집 범위 제한을 해제합니다.

---

#### `/setup-deploy` — 배포 설정

`/land-and-deploy`를 위한 일회성 설정. 배포 플랫폼(Vercel, Fly.io, Render 등), 프로덕션 URL, 헬스 체크 엔드포인트를 감지하여 CLAUDE.md에 기록.

**언제 호출:** 프로젝트에서 처음 `/land-and-deploy`를 쓰기 전.

---

#### `/setup-browser-cookies` — 브라우저 쿠키 가져오기

실제 Chrome/Arc/Brave/Edge의 쿠키를 헤드리스 세션으로 가져옵니다. 인증이 필요한 페이지 테스트용.

**언제 호출:** 로그인이 필요한 페이지를 `/qa`나 `/browse`로 테스트하기 전.

---

#### `/gstack-upgrade` — gstack 업그레이드

upstream 변경 사항을 가져오되, **three-way merge로 한글화를 보존**합니다. 새로 추가된 영어 콘텐츠의 번역도 제안.

**언제 호출:** "gstack 업데이트해줘", 새 버전 알림이 뜰 때.

## 업그레이드

Claude Code에서 `/gstack-upgrade` 실행. 또는 수동:

```bash
cd ~/.claude/skills/gstack
git fetch upstream
git merge upstream/main
bun run gen:skill-docs && ./setup
```
